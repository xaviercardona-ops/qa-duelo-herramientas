Dos palabras que se confunden

Librería o framework

Librería: tú la llamas

Tu código manda; la librería es una caja de herramientas.

Selenium WebDriver · Puppeteer · axe-core · Faker

const browser = await chromium.launch();

const page = await browser.newPage();

await page.goto(URL);

await browser.close();

Framework: él te llama

El framework manda: encuentra tus pruebas, las ejecuta y te entrega lo que necesitan.

JUnit · pytest · Jest · Cypress · Playwright Test

test('CA1: …', async ({ page }) => {

  // page ya viene abierto y se cierra solo

  await page.goto('/');

});

Inversión de control: «no nos llames, nosotros te llamamos». En el laboratorio nunca escribieron chromium.launch(): el framework abrió el navegador por ustedes.

Otra confusión frecuente

Dos significados de «framework»

1 · El producto

Una herramienta que se elige

Playwright Test, Cypress, Robot Framework, Selenium con JUnit…

Se descarga.

2 · La estructura propia

Una forma de trabajar que se construye

Carpetas, Page Objects, datos, informes y ejecución en integración continua.

Se construye.

La herramienta se descarga; el framework de verdad se construye encima.

Tres formas de controlar un navegador

Selenium

Cómo funciona

Un driver por navegador traduce las órdenes con el estándar W3C WebDriver.

Lenguajes

Java, Python, C#, JavaScript, Ruby

Navegadores

Chrome, Edge, Firefox, Safari

Esperas

Las programas tú

Cypress

Cómo funciona

La prueba corre dentro del navegador, junto a la aplicación.

Lenguajes

JavaScript y TypeScript

Navegadores

Chrome, Edge, Firefox (WebKit, experimental)

Esperas

Reintenta solo comandos y aserciones

Playwright

Cómo funciona

Un proceso externo controla el navegador por su protocolo.

Lenguajes

TypeScript y JavaScript, Python, Java, .NET

Navegadores

Chromium, Firefox, WebKit

Esperas

Espera sola; las aserciones reintentan

Selenium es una librería (necesita ejecutor); Cypress y Playwright Test son frameworks. En naranja, la que usaron.

El mismo criterio de aceptación

La misma prueba en tres herramientas

Selenium

Librería: faltan el ejecutor, las aserciones y los informes.

const driver = await new Builder().forBrowser('chrome').build();

await driver.get(URL);

await driver.wait(until.elementLocated(By.css('h3')), 5000);

assert.equal((await driver.findElements(By.css('h3'))).length, 8);

await driver.quit();

Cypress

Framework: todo incluido y reintenta solo.

it('CA1: el catálogo muestra 8 productos', () => {

  cy.visit('/');

  cy.get('h3').should('have.length', 8);

});

Playwright

Framework: todo incluido y espera solo.

test('CA1: el catálogo muestra 8 productos', async ({ page }) => {

  await page.goto('/');

  await expect(page.getByRole('heading', { level: 3 })).toHaveCount(8);

});

Verificación y validación · Tema 3.2

Después de la primera semana

El costo escondido: mantener

Versiones

Su repositorio fija las versiones (package-lock.json) y el CI usa npm ci: todos corren lo mismo.

Navegadores

npx playwright install descarga el navegador que esa versión espera: herramienta y navegador se actualizan juntos.

Inestabilidad

Una de las pruebas heredadas fallaba a veces: repetirla muchas veces la delató; un reintento la habría escondido.

Trazabilidad

test.fail(true, 'PRJ-12 · …') conecta cada prueba con su issue en Jira.

En 3.1 vimos que mantener pesa más que escribir. Hoy se suma: mantener también la herramienta.

La actividad de hoy

El duelo de herramientas

Tres herramientas, una misma regla. Prueban una y recomiendan cuál elegir para un cliente.

1

Portar

Tres criterios de la tienda, escritos en su herramienta.

2

Medir

Velocidad, estabilidad, código, diagnóstico y vigencia.

3

Comparar

Los datos de toda la clase, en un tablero.

4

Decidir

Matriz ponderada y un ADR para su cliente.

Dos sorteos

Una herramienta (Selenium, Cypress o Playwright con Cucumber) y un cliente, entre seis.

Equipos de tres

2 h 20 min en siete partes. La tienda corre en su equipo.

Lo que entregan

Las mediciones, la matriz y una página: lo que ganan y lo que pierden.
